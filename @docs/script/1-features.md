Howdy, GT School! I'm excited to show how Keystone turns reconciliation errors into a review flow that is useful, actionable, and safe.

01 · Orient — Start with the evidence

We begin with the current trust posture: what is verified, what is incomplete, and where to start. The counts come from read-only evidence, so an apparently clean number is never presented when the underlying evidence is missing. Here, the sync is complete for Generation 3, giving us a clear baseline for the rest of the review.

02 · Investigate — Find the conflicts

Next, we find where versioned checks detected a disagreement across systems. Open a conflict to compare the exact values, their lineage, and any guarded proposal. If the evidence needs to be updated, use Refresh evidence before continuing.

03 · Prioritize — See the bigger pattern

Once we understand the individual conflicts, we can step back and see the bigger pattern. Keystone groups related conflicts into workstreams so we can prioritize the highest-volume pattern before reviewing every piece of evidence. In this run, 14 patterns are available.

04 · Decide — Decide what to record

With the evidence and pattern in view, review the reasoning behind each proposed action. Then approve, reject, or hold what Keystone should record. These decisions update Keystone's trust layer and audit trail; source systems remain unchanged.

05 · Add context — Add support context

Finally, connect each support request to its student, household, source record, and conflict. That context gives the reviewer a clearer path from a request to the evidence that should inform the decision. This run has 50 extracted requests ready for that review.

That is the complete flow: orient on trustworthy evidence, investigate the disagreement, prioritize the pattern, decide what Keystone should record, and add the support context needed to make the review actionable. Keystone takes us from detection to explanation to safe human action without writing back to source systems.
